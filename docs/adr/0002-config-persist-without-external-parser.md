# config.persist 不依赖外部 TOML 处理器

`core/config.persist` 的写盘路径曾优先调用 mikefarah/yq（私有的 `_yq_try`），yq 不可用时落回 sed 文本替换。现已删掉 yq 分支，只留原生路径；`config.persist.update` 同时改为对含 `"` 或换行的值 fail-loud。

理由是两条路径能力等价而代价不等：

- **值转义等价**。原生路径的 `fs.replace` 已用 `string.escape.sed` 处理 sed 替换串的三个危险字符 `` \ `` / `&` / `|`；而含 `"` 或换行的值两条路径都会写坏 TOML——`_yq_try` 是把值直接拼进 yq 表达式字符串，并没有做 TOML 转义。唯一真实差异是 yq 能解析文件里既有的跨行 TOML 结构（多行字符串、跨行数组），而本仓库的配置文件都是自己生成的简单 `[section]` + `key = "value"` 形式。
- **性能**。原生路径约 11-14ms 且与文件大小无关；yq 路径 15-29ms 随规模线性增长，49 段时已是原生的约 1.8 倍、200 段时 2.4 倍。差额主要来自每次调用都要 `yq --version` 探测版本，而这个结果在一个进程内不会变。
- **行为可预测**。yq 重写整个文件，会重排格式并丢掉表头行内注释（`remove_section` 的 yq 分支还会删掉最后一个子表后留下空父表 `[packages]`）；原生路径只改目标行。
- **依赖**。少一个可选外部依赖。

**代价**：写盘路径只支持单行 `key = "value"`，值不能含 `"` 或换行。需要写复杂 TOML 结构的消费者不应使用 `config.persist`。

**被否决的替代方案**：保留 yq 分支但把版本探测结果缓存进全局变量。它只省掉探测那一次进程启动，`yq -i` 本身的启动开销仍在，缓存后仍比原生慢；而且此时 yq 提供的唯一额外能力（解析既有跨行结构）在本仓库无人使用。
